# Test matrix

## Automated (CI, no admin, no physical disks) - `pytest`
Disk images are generated by `tests/imgbuilders.py` (pure Python; FAT32 with LFN, exFAT, NTFS with fixups / fragmented /
sparse / compressed files, ext2 and ext4). Deleted files are created the way the OS deletes them, then recovered and compared
by SHA-256.

| Area | What is asserted |
|---|---|
| NTFS / FAT32 / exFAT / ext2 / ext4 | live + deleted listing, paths, bit-exact recovery, overwrite detection, unsupported cases flagged |
| Carving | JPG PNG GIF PDF DOCX/XLSX ZIP MP4 SQLite BMP at known offsets: offset, exact size, SHA-256; chunk-boundary hits |
| Partitions | MBR/GPT round trip, GPT CRC repair, lost-partition scan incl. NTFS backup-boot-sector location |
| Doctor | rebuild MBR, restore NTFS boot sector / FAT32 sector 6 / GPT copy, plan-only findings, dry-run default, **undo restores exact bytes** |
| Imaging | bad-sector map, retry passes, cancel/resume, pause, gzip, clone + verify, VHD footer |
| Backup | incremental, AES-256-GCM, wrong password, tamper + missing-blob detection, traversal-safe restore |
| Safety / licence / accounts | output-volume refusal (fail closed), typed confirmations, Ed25519 licence, attestation + audit log |
| Scale | 5 TiB synthetic disk: GPT, partition scan, carve-from-offset, cancel latency, 2 TB-file recovery cancel, ENOSPC stop, 200k-fragment reads, popcount estimates, session resume |
| RAID | all layouts bit-exact, degraded reads (RAID 5: any 1 of 4; RAID 6: any 1-2 of 6), detection on shuffled members |
| Virtual disks / editor | VHD, VHDX, VMDK, VDI round trips; deleted-file recovery through each; find across chunk boundaries; undoable sector write |
| CLI / GUI | end-to-end commands on images; headless GUI builds and scans an image |

**Limit of the automated tests:** the image builders and the parsers were written by the same author from the same reading of
the on-disk formats, so they can share a misunderstanding. Rows M1-M4 below (real Windows-formatted volumes) are the check.

## Manual - VM only (never a physical disk)
Use Hyper-V / VirtualBox / QEMU with a throw-away VHDX. Record result + Lavora version per row.

| # | Scenario | Setup | Expected |
|---|---|---|---|
| M1 | Real NTFS volume, deleted files | VHDX formatted by Windows, copy 50 files, delete 10, shut down, attach VHD read-only to host | `lavora-cli scan`/`recover` finds and restores the 10, hashes match |
| M2 | Real FAT32/exFAT volume | same with `format /FS:exFAT` | same |
| M3 | Real ext4 | create with `mkfs.ext4`, delete files | listed; ext4 recovery is best effort, note outcome |
| M4 | Quick-formatted volume | format an NTFS VHDX that had data | `partitions --scan` finds it; `carve` recovers files |
| M5 | Lost partition | delete partition in Disk Management | `partitions --scan` finds volume; `doctor` offers rebuild |
| M6 | Corrupted BCD (UEFI) | `bcdedit` delete default entry / rename BCD | boot fails; `plan windows-bcd` commands from WinRE fix it |
| M7 | Corrupted BCD (BIOS) | same with MBR VM | `bootrec` plan fixes it |
| M8 | Missing GRUB | wipe GRUB from a Debian VM disk | `plan grub` from a live USB fixes it |
| M9 | Dual boot after a Windows update overwrote GRUB | Windows + Ubuntu VM | `bootinfo` reports dual boot; GRUB plan restores the menu |
| M10 | Failing drive | VM disk with injected bad sectors (QEMU blkdebug) | `image` maps bad sectors, resume works |
| M11 | BitLocker volume | encrypt VHDX | Lavora cannot read it without unlocking; no bypass path exists |
| M12 | Backup scheduling | `schedule --install` in a VM | task runs; verification OK |
| M13 | Installer | install, launch (UAC), uninstall; upgrade 0.1.0 -> 0.1.1; downgrade refusal | clean install/uninstall, PATH entry added/removed, data kept on request |
| M15 | Real 5 TB disk | image + scan a real large disk (or a sparse VHDX on a big drive) | no hang; Ctrl+C / Cancel stops within a few seconds; resume works. Note the real speed |
| M16 | Real RAID | 3-4 member Linux md RAID5 / Windows Storage Spaces (not supported) | `raid-detect` finds the md geometry |
| M14 | Rescue USB | write ISO to a USB passthrough in a VM | boots, GUI starts (needs the ISO, Phase 3) |
