# Architecture notes

Layout (differs slightly from the brief: everything lives in the `lavora` package so imports work when frozen):

    lavora/core/      engine: device, partitions, fs/{ntfs,fat,ext}, recovery, carver, imaging, doctor, undo, backup, boot, ...
    lavora/cli/       `lavora-cli` command line
    lavora/gui/       PySide6 GUI (same core calls as the CLI)
    rescue/           Rescue ISO build recipe (Debian live-build), not built in this session
    installer/        installer.iss, build.ps1, wizard art, generated version/brand includes
    tests/            pytest + pure-Python disk image builders
    reference/        Zapi's installer.iss / build.bat / spec, kept for comparison (not shipped)

The CLI executable is `lavora-cli.exe` (not `lavora.exe`): Windows file names are case-insensitive, so it could not sit
next to `Lavora.exe` in one folder.

Brand constants: `lavora/brand.py` -> `tools/make_brand.py` -> `installer/brand.iss.inc`. The version has one source,
`lavora.__version__`, injected into the PyInstaller version resources and Inno (`/DAppVersion`).

## Zapi recon (what was reused)
Zapi is a PySide6 app built with PyInstaller one-dir (`COLLECT`), two executables (GUI + `-cli`) sharing one runtime, version
resources from a tool, installer artwork generated by a script, third-party notices generated from dist-info, and an Inno
Setup script with: modern wizard, EULA + info page, `UsePreviousAppDir`, `CloseApplications` plus a PowerShell routine that stops
only processes running from the install folder, downgrade protection (`/ALLOWDOWNGRADE`), an optional PATH task removed on
uninstall, a "keep my data?" prompt (`/REMOVEDATA`), self-removal of the uninstaller folder, and optional signing. Lavora keeps all
of that and changes: fresh AppId, `PrivilegesRequired=admin`, 64-bit only, system PATH, no per-user override, a Rescue-guide task.
Not copied: Zapi's name, paths, AppId, fonts, gRPC/YAML dependencies.

## Why our own read-only parsers (not pytsk3 / dissect.ntfs / TestDisk)
* **pytsk3** wraps The Sleuth Kit (mixed IPL/CPL/GPL components, native build; wheels for the newest Python are often missing)
  and cannot be pointed at our `BlockSource` abstraction without a shim. Good for cross-checking, awkward to ship.
* **dissect.ntfs** is a good NTFS parser, but the Dissect family is published under AGPL-3.0 (verify the current licence), which
  does not fit an MIT product.
* Our parsers are small, pure Python, read-only by construction, run on any `BlockSource` (image, device, partition slice), and are
  testable against generated images. Trade-off: less battle-tested than TSK/TestDisk on odd real-world volumes
  (attribute lists, compression, EFS, journals). Plan: keep TSK/TestDisk/PhotoRec as optional *external executables* that can
  cross-check results (manual test matrix) and fill gaps; they are never linked in.
